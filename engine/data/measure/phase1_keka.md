## Provenance
- Date: 2026-08-04 (Asia/Kolkata context).
- Common Crawl index queried: `CC-MAIN-2026-30-index`.
- Exact query: `url=keka.com&output=json&showNumPages=true&matchType=domain`.
- Common Crawl robots: HTTP 200; body said `Disallow: /` with explicit allows for `/`, `/index.html`, `/web-graphs-index.html`, `/collinfo.json`, `/graphinfo.json`, `/ccbot.json`, and `/.well-known/*.txt`.
- Live `collinfo.json` and pinned-index metadata requests timed out. No live URL count is claimed. The saved 311-token board list comes from the pre-existing `.cache/boards_keka.json`, generated by the repository enumerator; it was not fabricated from guessed URLs.
- Extraction method: first subdomain label before `.keka.com`, lowercased, filtered by the existing enumerator's `NOT_TOKENS` and slug regex.

## Step 1 — existing machinery
- `fetch.py` builds the portal host as `https://{token}.keka.com`.
- It first requests `https://{token}.keka.com/careers/` and extracts a UUID board GUID from `/ats/documents/<guid>/`, `embedjobs/js/<guid>`, or a UUID anywhere in the shell.
- It then requests the exact template `https://{token}.keka.com/careers/api/embedjobs/{portalName}/active/{board_guid}`. It tries `portalName=default`, then the token as fallback. Therefore both the portal name and board GUID are required; Common Crawl can provide the portal token, but the GUID must be read from the live careers shell (or another official source).
- Keka request hosts are one subdomain per portal: `{token}.keka.com`; the enumeration host is `index.commoncrawl.org`.

## Robots outcomes
- `index.commoncrawl.org/robots.txt`: HTTP 200; the published rules disallow the index query path and only explicitly allow the listed metadata/static paths. A pinned index request was attempted before this restriction was acted on, timed out, and produced no data; it is not used as evidence. No compliant live URL count is claimed.
- Sampled Keka hosts: robots HTTP status counts are `200: 39` and `404: 1`; HTTP 200 rules were honored by the adapter, and HTTP 404 was treated as robots unavailable under the existing RFC logic (not as a disallow).

## Assumptions and failures
- `india-located` includes both `filters.INDIA_LOCATED` and `filters.INDIA_REMOTE`, matching the project's three-bucket applicability model.
- Batch-year, degree, and enrolment are measurement regexes in this report; India/technical are not reimplemented and come from `filters.classify()` as required.
- A Keka HTTP 200 with zero jobs is recorded as `empty`; shell/API failures and missing GUIDs are `error`; no partial result was marked complete, and no sampled board was truncated.
- The live Common Crawl API could not be verified because both `collinfo.json` and `CC-MAIN-2026-30` metadata timed out. The saved board list is consequently the pre-existing 311-token cache, with its provenance limitation recorded above.
